# OFFZONE Badge Archive

Статический сайт-архив коллекции бейджей и аддонов с конференций OFFZONE.
Чистые HTML/CSS/JS, без сборки и зависимостей — готов к публикации на GitHub Pages.

## Структура

```
badges/
├── index.html
├── assets/
│   ├── css/style.css        — оформление
│   ├── js/data.js           — ★ ВСЕ ДАННЫЕ КОЛЛЕКЦИИ здесь
│   ├── js/app.js            — логика рендера (трогать не нужно)
│   ├── img/                 — фото бейджей и аддонов
│   └── models/              — .glb 3D-модели (сканы)
└── README.md
```

## Как добавить год / бейдж / аддон

Всё редактируется в `assets/js/data.js`:

1. **Новый год** — скопируйте блок события в `events[]`, задайте `id`, `title`, `date`, `location`.
2. **Бейдж года** — заполните `badge`: `description`, `source` (ссылка-источник),
   `photos` (первое фото — главное, остальные уходят в галерею).
3. **Аддон** — добавьте объект в общий `addons[]` (в корне `SITE_DATA`, один аддон — одна запись,
   даже если он был на нескольких конфах):

| Поле | Значение |
|---|---|
| `id` | уникальный глобально (латиница/цифры/дефис) |
| `years` | массив id событий, где аддон встречался, напр. `["offzone-2023", "offzone-2024"]` |
| `category` | `partner` (партнёрский, со стендов), `soldering` (зона пайки: официальные за старые бейджи и кустарные), `community` (комьюнити/спикеры) |
| `company` | компания или автор |
| `obtainedFor` | за что выдавался |
| `rarity` | `common` → `uncommon` → `rare` → `epic` → `legendary`, или `unknown` — если редкость неизвестна |
| `rarityNote` | тираж, напр. «выпущено всего 10 шт.» или «продавался в магазине» |
| `photos` | массив путей, первое — главное |
| `model3d` | путь к `.glb` или `null` |

Порядок аддонов на странице года: по умолчанию — порядок в `addons[]`; для конкретного
года можно задать `addonOrder: ["id1", "id2"]` у события — перечисленные пойдут первыми.

Вкладки событий делятся на два блока: `id`, начинающиеся с `offzone`, попадают в **OFFZONE**,
все остальные — в **Другое**. Переопределить можно полем `group: "offzone" | "other"` у события.

Фото кладите в `assets/img/<год>/`, модели — в `assets/models/<год>/`.

## 3D-модели

Когда отсканируете предмет, экспортируйте в **glTF binary (`.glb`)**,
положите в `assets/models/` и укажите путь в `model3d`. Просмотрщик
(`<model-viewer>` от Google, подключён по CDN) появится на сайте автоматически:
модель можно вращать мышью/пальцем.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и запушьте содержимое папки в корень:

   ```bash
   git init
   git add .
   git commit -m "badge archive"
   git remote add origin git@github.com:<user>/<repo>.git
   git push -u origin main
   ```

2. В репозитории: **Settings → Pages → Build and deployment →
   Source: Deploy from a branch → Branch: `main`, folder: `/ (root)` → Save**.

3. Через минуту сайт будет доступен по адресу
   `https://<user>.github.io/<repo>/`.

Никаких настроек сборки не нужно — Pages отдаёт статику как есть.
Если сайт лежит не в корне репозитория, а в подпапке `badges/`, выберите её
в настройках Pages (folder: `/badges` из ветки `main`).

## Локальный просмотр

Просто откройте `index.html` в браузере — сайт работает и с `file://`
(данные подключаются скриптом, без fetch).

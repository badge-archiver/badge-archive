# Badge // Archive

Архив бейджей и аддонов с конференций. Чистый статик: HTML/CSS/JS без фреймворков,
контент — просто папки с фото и `meta.json`. Сборка и валидация — Node-скриптом
в CI (GitHub Actions → GitHub Pages), без рантайм-зависимостей.

## Структура

```
├── badges/<slug>/        бейджи: meta.json + фото (01.jpg, 02.png, …)
├── addons/<slug>/        аддоны: meta.json + фото
├── site.config.json      справочник конференций/категорий/редкостей + список фасетов
├── src/                  страницы (index = бейджи, addons/, 404) + css/js/шрифты/иконки
├── item-editor/          локальный GUI-редактор meta.json (npm run editor)
├── tools/
│   ├── build.mjs         валидация → manifest.json (+ размеры фото) → dist/
│   ├── preview.mjs       локальный сервер dist/ (как gh-pages, с 404)
│   ├── make-favicon.mjs  перегенерация PNG-фавиконок из favicon.svg
│   ├── test-facets.mjs   юнит-прогон фасеточного движка
│   └── test-browser.mjs  браузерные проверки (Playwright + Chromium)
└── .github/workflows/    deploy.yml — сборка и деплой на GitHub Pages
```

## Как добавить айтем

1. Создай папку `addons/my-addon-slug/` (слаг: строчная латиница/цифры/дефисы).
2. Сложи туда фото: `01.jpg`, `02.png`, … — **все картинки папки попадают в галерею**,
   порядок сортировки по имени, первая = обложка. Никаких списков в JSON.
3. Положи `meta.json`:

```json
{
  "name": "Название аддона",
  "event": "offzone",
  "year": 2025,
  "manufacturer": "Кто сделал",
  "category": "partner",
  "rarity": "uncommon",
  "rarityNote": "тираж/пояснение",
  "obtainedFor": "за что выдавался",
  "description": "описание",
  "source": "https://ссылка-на-источник",
  "schematic": "https://ссылка-на-исходники-проекта",
  "tags": ["интерактив"],
  "order": 1
}
```

Бейдж — то же самое в `badges/<event>-<year>/`:

```json
{
  "name": "Бейдж OFFZONE 2025",
  "event": "offzone",
  "year": 2025,
  "location": "Москва",
  "description": "…",
  "source": null,
  "order": 1
}
```

Обязательные поля: `name`, `event`, `year`. Остальное — по мере наличия.
Опционально: `"model3d": "model.glb"` (файл кладётся в ту же папку),
`"cover": "03.jpg"` (обложка не первая по сортировке), `"order"` (положение в годовой
секции), `"todo"` (пометка «найти инфу», на сайте не показывается),
`"schematic"` («Исходники проекта» — репозиторий кода/схемотехники/герберов; работает
и у аддонов, и у бейджей, обязателен протокол `https://`).

**Ссылки в описаниях**: просто вставляй голый URL (`подробнее: https://site.tld/page`)
или markdown-вариант с подписью (`[статья на хабре](https://habr.com/…)`).
Работает в `description`, `obtainedFor` и `rarityNote`.

Связи: пара `(event, year)` аддона автоматически линкуется с бейджем той же пары —
на модалке бейджа появятся его аддоны, в карточке аддона — ссылка на бейдж.

## Валидация (падает сборка = красный CI)

- слаг из `^[a-z0-9][a-z0-9-]*$`, уникальность;
- `event` существует в `site.config.json`;
- `category` / `rarity` из справочника (rarity можно не указывать → «Неизвестно»);
- у бейджа ≥ 1 фото; пара `(event, year)` уникальна;
- аддон с `(event, year)` без бейджа — warning в логе (допустимо);
- формат картинок сверяется по магическим байтам: webp-файл с расширением .jpg — warning;
- `schematic` — если указан, обязан быть URL с `http(s)://` (иначе ссылка на сайте уйдет в относительный путь);
- неизвестные поля meta.json — warning (ловим опечатки вроде `manufaturer`).

## Фасеты (фильтры)

Список фильтров страницы `/addons/` задаётся в `site.config.json` → `facets`.
Новое поле фильтра = строка в массиве. Значения и счётчики вычисляются из данных
автоматически. Справочники (`events`, `categories`, `rarities`) задают лейблы,
цвета чипов и порядок сортировки значений. Ключи — lowercase-слаги, отображение —
в `label` (например, ключ `dc78422`, лейбл `DC78422`).

Состояние фильтров живёт в URL (`?year=2025&manufacturer=Т-Банк`), открытая
карточка — в хеше (`/addons/#slug`): ссылками можно делиться, back закрывает модалку.
Чипы в карточках — тоже фильтры: клик включает/выключает фасет.

## Локально

```bash
npm run build     # валидация + dist/ + manifest.json
npm run serve     # сервер dist/ на :4173 (gh-pages-поведение, включая 404)
npm run preview   # build + serve разом
npm run editor    # GUI-редактор карточек на :4174 (пишет meta.json напрямую)
npm test          # юнит-прогон фасетов
```

### Редактор карточек (`npm run editor`)

Открывает `http://localhost:4174`: слева дерево бейджей (по конференциям
и годам) и аддонов (по годам) с поиском, справа — форма карточки: текстовые
поля, редкость/категория/конференция — селекты из `site.config.json`,
изготовитель — ввод с подсказками из существующих значений, теги через запятую.
Снизу «сохранить» (пишет `meta.json`, фото в папку кидаются мимо редактора).
Кнопка «проверить сборкой» гоняет валидацию `tools/build.mjs` прямо из UI.
Фото в айтем кладутся файлами — редактор только метаданные.

Или просто двойной клик по `start.cmd` (сборка + браузер + сервер).

Требуется Node ≥ 18. Рантайм-зависимостей — ноль. Для браузерных тестов —
`npm i && npx playwright install chromium` (dev-зависимость, сайту и CI не нужна).
Не открывай `dist/index.html` через file:// — fetch манифеста заблокирован,
нужен сервер (`start.cmd` / `npm run serve`).

## Деплой на GitHub Pages

Пуш в `main` → валидация → сборка → деплой (`deploy.yml`). Сломанный `meta.json` =
красный CI с конкретной ошибкой, а не молча умерший сайт.

Перед первым деплоем один раз: Settings → Pages → Source: **GitHub Actions**.
